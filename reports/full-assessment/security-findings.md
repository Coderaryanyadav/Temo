## Detailed Vulnerability Profiles

### FINDING-PAY-01: Client Verification Payload Omits Razorpay Cryptographic Signature
- **Severity**: **High**
- **CVSS 4.0 Vector**: `CVSS:4.0/AV:N/AC:L/AT:P/PR:L/UI:N/VC:N/VI:H/VA:N/SC:N/SI:H/SA:N` (Score: 7.3)
- **Affected Component**: [main.dart.js](file:///Users/aryan/KNOT-Security/reports/flutter/main.dart.js) (Function `cg3` at pos 5651601)
- **Description**:
  When a Razorpay checkout modal finishes successfully, the Razorpay SDK returns `razorpay_payment_id`, `razorpay_order_id`, and `razorpay_signature`.
  However, in `main.dart.js`, function `cg3` packages only the order ID into the verify request:
  ```javascript
  cg3(a) {
    return A.k(
      $.eR().a9V("/gift-cards/txn/verify", A.a(["order_id", a], t.N, t.S), t.z),
      $async$CE
    );
  }
  ```
  The cryptographic HMAC signature generated by Razorpay is discarded on the client and never sent to the backend.
- **Security Impact**:
  Because the backend does not receive `razorpay_signature`, it cannot mathematically verify the authenticity of the client callback without making an external server-to-server HTTP request to Razorpay. If the backend fails to make this external call, an attacker could submit arbitrary or unpaid `order_id` values to claim wallet credits.
- **Remediation**:
  1. Update the Flutter client to send `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`.
  2. In the backend handler, compute:
     $$\text{expected\_sig} = \text{HMAC-SHA256}(\text{order\_id} + "|" + \text{payment\_id}, \text{RAZORPAY\_SECRET})$$
     Reject any verification request where the signature does not match.

### FINDING-PAY-02: Potential Double-Crediting Race Condition on Concurrent Verification
- **Severity**: **High**
- **CVSS 4.0 Vector**: `CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:N/VC:N/VI:H/VA:N/SC:N/SI:N/SA:N` (Score: 7.1)
- **Affected Component**: Backend `verify` endpoint and transaction database schema.
- **Description**:
  If multiple requests to `POST /gift-cards/txn/verify` for the same `order_id` arrive simultaneously, and the backend lacks database-level row locking (`SELECT FOR UPDATE`) or a unique database constraint on the credit ledger, multiple worker threads could simultaneously observe `status == "PENDING"`, apply multiple credits, and commit duplicate balance updates.
- **Security Impact**:
  Financial loss due to duplicated stored-value wallet credits resulting from a single legitimate payment.
- **Remediation**:
  1. Enforce atomic status transitions:
     ```sql
     UPDATE wallet_transactions SET status = 'COMPLETED' 
     WHERE gateway_order_id = :id AND status = 'PENDING';
     ```
     If the query updates 0 rows, abort immediately.
  2. Add a `UNIQUE` constraint on `(transaction_id, entry_type)` in the `wallet_ledger` table.

### FINDING-PAY-03: Webhook Endpoint Requires Strict Constant-Time HMAC Signature Check
- **Severity**: **Medium**
- **CVSS 4.0 Vector**: `CVSS:4.0/AV:N/AC:H/AT:N/PR:N/UI:N/VC:N/VI:H/VA:N/SC:N/SI:N/SA:N` (Score: 6.8)
- **Affected Component**: `/webhooks/razorpay` Endpoint
- **Description**:
  Webhooks operate without user session authentication and must rely entirely on cryptographic validation of the `X-Razorpay-Signature` header. If the signature verification uses standard string equality (`==`) rather than a timing-safe comparison, timing side-channels can theoretically be exploited.
- **Remediation**:
  Use `hmac.compare_digest` in Python or `crypto.timingSafeEqual` in Node.js on the raw request body buffer before JSON parsing.

### FINDING-PAY-04: Transient Checkout Transaction Data Persisted in Browser Storage
- **Severity**: **Low**
- **CVSS 4.0 Vector**: `CVSS:4.0/AV:L/AC:L/AT:N/PR:N/UI:P/VC:L/VI:N/VA:N/SC:N/SI:N/SA:N` (Score: 4.0)
- **Affected Component**: [main.dart.js](file:///Users/aryan/KNOT-Security/reports/flutter/main.dart.js) (pos 5586083)
- **Description**:
  The client stores checkout metadata in localStorage under `gift_card_checkout_txn:<id>`:
  ```javascript
  $.boY().aRR(
    "gift_card_checkout_txn:" + j,
    A.a(["order_id", m.h(n, "order_id"), "razorpay_payment_gateway_response", m.h(n, "razorpay_payment_gateway_response")], t.N, t.z)
  );
  ```
- **Security Impact**:
  Transaction IDs and gateway order responses remain in client storage after checkout. While not critical secrets, they can be read by other scripts executing within the origin.
- **Remediation**:
  Clear `gift_card_checkout_txn:<id>` immediately upon modal closure or completion.
